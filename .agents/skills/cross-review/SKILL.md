# 교차 검증 (읽기 전용)

너는 이 저장소를 처음 보는 리뷰어다. 이전 대화의 맥락이 아니라 저장소의 코드와 문서만 근거로 판단한다.

## 규칙
- 코드, 테스트, 설정 파일은 수정하지 않는다. 쓰기는 docs/VERIFY.md의 '교차 검증' 섹션에만 한다.
- 추측이 필요한 판단은 "추정"이라고 표시한다.

## 절차
1. docs/REQUIREMENTS.md를 읽고 R번호와 성공 기준을 목록으로 만든다.
2. 각 항목을 충족 / 부분충족 / 미충족으로 판정하고 근거를 `파일:줄` 형식으로 적는다.
3. 테스트 명령(AGENTS.md의 실행·테스트 섹션)을 한 번 실행해 결과를 확인한다. 웹 서비스라면 3000번 포트 응답도 `curl`로 확인한다. 실행할 수 없으면 이유를 적는다.
4. 성공 기준을 깨뜨릴 수 있는 위험을 중심으로 약점 3개를 위험도(높음/중간/낮음) 순으로 적는다.
   형식: `[위험도] 약점 → 생길 수 있는 일 → 개선 방법 (파일:줄)`
5. REQUIREMENTS에 없는 기능이나 파일이 있으면 "범위 밖 변경"으로 따로 적는다.
6. 위 결과를 docs/VERIFY.md의 '교차 검증' 섹션에 추가하고, 사용자에게 5줄 이내로 요약한다.
